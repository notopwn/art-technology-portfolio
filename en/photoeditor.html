PhotoEditor

App screen before import · Central canvas / Tools on the left / Layers and properties on the right

WHY I BUILT IT

Add a tool.
Keep the work intact.

I started by wanting to build a macOS image editor. As I added effects and GIF editing to layers and brushes, something mattered more than the number of tools: changing tools should not mean starting over.

01 / LAYERS

Keep originals and edits apart.

Original assets and adjustment values are preserved separately. Layers, masks, and effects can be combined, then adjusted again.

02 / SELECTION

Selections you can reuse.

Color- and object-based selections can become masks and alpha channels. A temporary outline becomes material for the next edit.

03 / ANIMATION

From one image to many frames.

Frames and timing share the same layer-based foundation. Still-image editing connects to GIF playback and export.

ONE DOCUMENT, MANY EDITS

Not just the result.
The way it was edited.

A flattened image leaves little room for revision. I separated the editable project from the image delivered to others. Layers, selections, effects, frames, and referenced assets remain in the project.

New tools share the same document and Undo system. Save a project, reopen it, and continue editing.

MAKING IT FEEL RIGHT

Using it exposed
the small interruptions.

Not being able to move an image right after adding it, or not knowing where a frame would land, broke the editing flow. I described those problems to coding agents, checked the results, and refined the workflow.

01

Add it, then move it.

I reviewed tool and editing state so creating an image or text could lead naturally into the next action.

02

See where the frame will land.

I refined GIF frame dragging and reordering, checking timing, playback, and export as one workflow.

03

Keep moving around the canvas.

I checked trackpad panning direction and lag, then adjusted how input is batched and how rendering work is reused.

PREVIEW TO FILE

What you preview
is what you save.

Before exporting a still image or GIF, preview the actual encoded output and its file size. Saving writes those same bytes, keeping the preview and delivered file aligned.
